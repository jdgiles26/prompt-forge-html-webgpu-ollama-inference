# Prompt Forge — Testing Infrastructure

## Test infrastructure for THIS app (the app itself)

The app is a single standalone HTML file (`prompt-forge.html`). It has **no unit tests of internal JS functions in isolation** — there is no JS bundler, no test runner for pure logic, no `*.test.js` that imports the module's functions. Instead, the entire test suite is **end-to-end browser automation via Playwright** that loads the real page (file:// or http://localhost) and exercises the DOM/UI.

### Test files (all at repo root, none inside a `test/` or `__tests__/` dir)
| File | Runner | Count | What it covers |
|---|---|---|---|
| `test_features.js` | Playwright (Chromium, `file://` page) | 117 tests (25 `withPage` groups) | FORGE view DOM/UI: sections, params, modes, templates, backend toggle, history, validator, splitter, shortcuts. |
| `test_tabs.js` | Playwright (Chromium, `http://127.0.0.1:8765` via `serve.py`, mocked Ollama at network layer) | 56 tests | ASSEMBLY LINE + AGENT FORGE: tab switching, model pool, stages, run, zip, interview, perms. |
| `test_e2e_project.js` | Playwright | 76 tests | Project pipeline: stream a forged payload → parse FILE blocks → build zip → write artifacts to `test_output/`. |
| `test_zip_runs_tdd.js` | Node + `adm-zip` + real `pytest` (shell `execSync`) | 8 tests | Unzip `test_output/complete_project.zip` into `test_output/sandbox/`, run `pytest` (must be RED), patch `src/after/main.py`, run `pytest` (must be GREEN). |
| `test_webgpu_local_http.js` | Playwright over `serve.py` | ~5 tests | WebGPU smoke + validate `#browserModel` option IDs against WebLLM's `prebuiltAppConfig`. |
| `list_webllm_models.js` | Playwright | (helper, not a test) | Enumerates WebLLM prebuilt model list to regenerate the dropdown. |

### Test runner & commands (`package.json`)
```json
"scripts": {
  "serve": "python3 serve.py",
  "test": "node test_features.js && node test_tabs.js && node test_e2e_project.js && node test_zip_runs_tdd.js && node test_webgpu_local_http.js",
  "test:features": "node test_features.js",
  "test:e2e": "node test_e2e_project.js",
  "test:zip": "node test_zip_runs_tdd.js",
  "test:webgpu": "node test_webgpu_local_http.js",
  "test:tabs": "node test_tabs.js",
  "models": "python3 serve.py & sleep 1 && node list_webllm_models.js ; pkill -f 'python3 serve.py'"
}
```
- Run with: `npm install` (installs `playwright` + `adm-zip` dev deps) → `npx playwright install chromium` → `npm test`.
- Each test file is a standalone Node script with its own `passed`/`failed` counters and `console.log` output; there is **no unified test framework** (no Jest/Mocha/Vitest). Assertions are hand-rolled `rec(name, ok, detail)` / `record(...)` helpers.
- `test_tabs.js`, `test_webgpu_local_http.js`, and `list_webllm_models.js` spawn `python3 serve.py` as a child process (PORT 8765) and route requests through it. `test_tabs.js` mocks Ollama by intercepting `/api/tags` and `/api/generate` with deterministic canned responses (fake model list `mock-tiny:1b`/`mock-mid:7b`, fake FILE payload).
- `test_features.js` loads the page via `file://` directly (no server) and tolerates expected network errors (Ollama offline, CDN failures) via `EXPECTED_ERROR_PATTERNS`.

### Known / documented test failures (from README, pre-existing on HEAD)
- `test_features.js`: 116 pass / 1 fail — Ollama now live on the VM → the Forge view's relative `/ollama` URL fetched from `file://` fails (environmental, pre-existing).
- `test_zip_runs_tdd.js`: 7 pass / 1 fail — PEP 668 blocks `pip install pytest` on the VM; fix with `pip install --break-system-packages pytest`.
- `test_webgpu_local_http.js`: 2 pass / 1 fail / 1 skip — headless Chromium lacks `shader-f16` WebGPU extension (the live inference skip); real Chrome has it.
- `test_tabs.js`: 56 pass / 0 fail (mocked, deterministic).

## test_output directory and guidance files

### `/opt/prompt-forge/test_output/` (gitignored — see `.gitignore:366` `test_output/`)
This is **not a test source directory** — it is the **output/artifact directory** produced by `test_e2e_project.js` and consumed by `test_zip_runs_tdd.js`. Contents (current):
- `README.md` — auto-generated by `test_e2e_project.js` ("Generated by test_e2e_project.js on ..."). Lists `complete_project.zip`, `forged_payload.txt`, `validation_report.txt`.
- `complete_project.zip` — the forged TDD package (6.6 KB).
- `forged_payload.txt` — the streamed multi-file payload (5.1 KB).
- `validation_report.txt` — in-page validator output.
- `pytest_red_output.txt` / `pytest_green_output.txt` — captured pytest output (RED before impl, GREEN after).
- `sandbox/` — the unzipped project where `test_zip_runs_tdd.js` runs `pytest`. Contains the generated `README.md`, `CLAUDE.md`, `AGENTS.md`, `DONE.md`, `Makefile`, `.gitignore`, `requirements.txt`, `prompt-forge.json`, `src/before/`, `src/after/`, `tests/`.

### Guidance files
- **`/opt/prompt-forge/test_output/README.md`** — only the auto-generated artifact manifest (see above). No testing constraints/instructions.
- **`/opt/prompt-forge/test_output/AGENTS.md`** — **does not exist** (empty `cat` output).
- **`/opt/prompt-forge/test_output/CLAUDE.md`** — **does not exist.**
- **`/opt/prompt-forge/test_output/sandbox/AGENTS.md`** — exists but is a **generated artifact** (part of the forged zip), 165 bytes: `"# Agent Workflow\n- **Architect** — owns CLAUDE.md, never edits code.\n- **Implementer** — edits only src/after/.\n- **Reviewer** — runs make test, fills DONE.md."` It is **not** guidance for working on Prompt Forge itself; it is a sample output file the app produces.
- **`/opt/prompt-forge/test_output/sandbox/CLAUDE.md`** — exists but is a **generated artifact** (the forged sample Claude Code system prompt for the "Token Counter" TDD sample), 1.7 KB. Again, not guidance for this repo.
- **`/opt/prompt-forge/test_output/sandbox/README.md`** — generated sample project README ("Token Counter — TDD Sample"). Not guidance.

### Constraints derived from these files
There are **no AGENTS.md/CLAUDE.md guidance files for the `test_output/` directory** (the subdirectory guidance referenced in the orchestrator's task prompt — `test_output/README.md`, `test_output/sandbox/AGENTS.md`, `test_output/sandbox/CLAUDE.md`, `test_output/sandbox/README.md` — consists of the auto-generated artifact manifest and the *forged sample project's* files, not instructions for editing Prompt Forge). The only real constraints:
1. `test_output/` is **gitignored** (`.gitignore:366`) — artifacts there should not be committed; they are regenerated by `test_e2e_project.js`.
2. `test_output/sandbox/` is overwritten by `test_zip_runs_tdd.js` on each run (it unzips `complete_project.zip` there and runs `pytest`); do not place manual edits there expecting persistence.
3. To make the zip-tdd suite green, `pytest` must be installed via `pip install --break-system-packages pytest` (PEP 668 workaround on this VM).

## Summary
- **Test framework**: Playwright (browser E2E) + hand-rolled Node scripts + real `pytest` for the TDD-zip proof. No unit-test framework, no bundler, no isolated JS function tests.
- **No dedicated test directory** for app source — all test files live at repo root.
- `test_output/` is a gitignored artifact directory, not a test-code directory; its AGENTS/CLAUDE/README files are either auto-generated manifests or forged sample-project outputs, not development guidance.
